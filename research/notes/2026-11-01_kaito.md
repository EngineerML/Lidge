# kaito (SN30 benchmark-phase winner) walkthrough (2026-11-01)

Static reading of `released/set30/017_kaito_v0_bceff3ed/agent.py` (1,606 lines, never run).
Score 10/29 (0.345) at $0.141/problem; ~48-64% of SN30's emission share as benchmark winner.

## Shape

One model, one tool loop, strong guard rails. No multi-agent search, no sampling of several
candidates, no task-type routing.

| Part | What it does |
|---|---|
| Config | `openai/gpt-6.1-sol`, reasoning effort medium, 16k output tokens; fallbacks `openai/gpt-6-luna`, `anthropic/claude-haiku-5.5`; local price table for cost estimates |
| Budgets | stop at 90% of `AGENT_TIMEOUT` minus 30 s (hard end at timeout - 10 s); spend at most 85% of `RIDGES_MAX_COST_USD` |
| Opening message | task + working dir + minutes available + a shell **survey** (ls, find depth 3, size, git log/status, installed toolchains, pip freeze, CPU/RAM/disk) + up to 10 **files containing the task's rare words** (`git grep`, quoted terms weighted 3x, test files down-weighted) |
| Tools | `bash` (fresh shell, timeout <= half the time left, `background=true` for long jobs), `bash_poll` (up to 4 jobs), `write_file`, `edit_file` (exact unique match or `replace_all`), `view_file` (images/PDFs sent to the model), `finish(result_files, summary)` |
| Edit feedback | after each write/edit, a syntax check by extension (node --check, bash -n, ruby -c, php -l, gofmt, ...) |
| System prompt | deliverables must be regular files at the exact path/format inside the workdir; scratch under `/tmp/work`; batch independent tool calls; compute, don't estimate; reproduce every worked example exactly; check by running; re-read the task; one definite answer |
| Finish gate | first `finish` is always refused with: list of changed files + the task again + "compare point by point, run the examples, remove scratch files, then finish again". Also rejects missing/symlink/outside/empty-dir results, warns on >200 new files |
| Nudge | if nothing changed after 40% of the time or 50% of the budget: "put a first version at the exact path now" |
| LLM client | prompt-cache marks, budget pre-check per call, drops to a cheaper model when the next call is unaffordable, rotates model on refusal/invalid-model, strips old reasoning or temperature on errors, compacts context near 220k tokens |
| Patch | own git snapshot in a separate index at start; final diff keeps small git-ignored files, drops big new files (>10 MB unless named), nested repos, symlinks, bytecode; binary patches when needed; then reverse-applies the diff and `git apply --check`s it against the restored tree |
| Advisor | optional planner/reviewer model; **off in production** (`ADVISOR_MODELS` empty unless the `PS_ADVISOR` env var is set) |

## Why it works

Most points in Problem Solving are lost on format, path, unchecked answers and running out of time,
not on raw model ability. kaito's code targets exactly those: the survey and rare-term hints cut
exploration steps, the prompt forces execution-based checks, the finish gate forces one extra
verification pass, and the patch builder makes sure what was produced is what gets graded.

## Weak spots / room above it

- One pass, one model; nothing to reduce variance across the 3 validator runs.
- Reviewer exists but is disabled; the gate is self-review by the same model.
- Medium reasoning effort, 85% of budget: leaders above it (11-15/29) spend $0.16-0.17.
- Exact copies (wren, sundial, saffron) score the same and earn nothing; improvements must be real.
